# Prefill-to-decode transfer: model and results

Canonical code-to-model reference for the prefill-to-decode KV-cache transfer
subsystem under `TpuSyncVerify/Transfer/`. Citations are to the baseline commit
in [verification/README.md](../../README.md) §Status.

This file is the short map: routing from C++ to the owning Lean module, what is
proved, the model boundaries, the assumptions and the mutants. Each `trace_*`
theorem's docstring names the C++/Python test it replays (64 upstream tests:
58 C++ and 6 end-to-end, counting each JAX/PyTorch twin once; the five
`TPU_RAIDEN_DATA_CONN_REUSE` tests are noted as unmodelled in `Send.lean`), and
each module's `## Source map` table gives the resolved line ranges.

## Shipping C++ vs. modelled design alternatives

Two modules parameterize both the **shipping C++ behavior** and a
**non-shipping design alternative** so both can be compared formally:

| Module | Parameter | Shipping C++ behavior | Modelled design alternative (not in shipping C++) |
|---|---|---|---|
| `PrefillDecode/PeerIsolation.lean` | `SlotPolicy` | **`SlotPolicy.unboundedPerPeer`**: `StartRead` acquires staging from `StagingBlockAllocator` (`TransferReceiveSession::Create`) with no per-peer cap. `numSlots` wedged reads to `Peer.sick` exhaust `freeSlots = 0` and cause healthy reads to fail slot admission (`trace_sick_peer_starves_staging_slots`, matching `ControlHandshakeTest.DISABLED_SickPeerStarvesStagingSlotsForHealthyPeer`). | **`SlotPolicy.perPeerQuota maxPerPeer`**: Caps staging slots held by any single `remote_endpoint` at `maxPerPeer < numSlots`. Proves `Peer.sick` holds at most `maxPerPeer` slots (`reachable_sick_staging_le_quota`) and healthy peers are always admitted (`reachable_quota_admits_healthy`). |
| `PrefillDecode/ReceivePoll.lean` | `stepM (poll : Bool)` | **`stepM true` (`poll = true`)**: `CompleteReadWithDetails` checks `session->IsReadyToComplete()` and calls `session->Finish()`. Safe (`Recv.reachable_safe`), but if the poll fires in the window after all H2D futures are ready and before the last callback runs, the last callback sees `draining_` and skips `RecordTransferDuration`/`RecordH2dComplete`/`RecordEnd` (`trace_poll_skips_metrics`). | **`stepM false` (`poll = false`)**: Removes the poll-side `IsReadyToComplete` finish so only the last H2D callback finishes a `num_layers() > 0` session (requiring a zero-layer receive to finish at creation like `TransferSendSession::StartPush` on `total_layers == 0`). Preserves all safety and settlement properties (`noPoll_safe`, `noPoll_can_settle`) and guarantees metrics on success (`noPoll_metrics_on_success`). |

*(Note: in `PeerIsolation.lean`, `Backend.tcpBlocking` and `Backend.grpcAsync` are both shipping C++ control-plane backends.)*

| Publication correctness (single request) | `Pipeline.reachable_safe` (`PublicationCorrect`) | `recv.published = some true → decodeHbm = good n` |

(`Recv.Publication`: `done_recving → every H2D callback ran OK`;

## System & model boundaries (horizontal, upper, and lower)

The prefill-to-decode Lean model sits between three explicit boundaries:

| Boundary | In scope / Modelled in Lean | Out of scope / Abstracted at boundary |
|---|---|---|
| **1. Horizontal boundary (Prefill-to-Decode / Symmetric vs. Other Subsystems)** | **Prefill-to-decode ("symmetric") KV-cache transfer**: layer-wise producer registration (`NotifyForRead` / `register_read`), consumer pull & load (`StartRead` / `start_read`), D2H → H2H → H2D pipeline (`TransferSendSession`, `TransferReceiveSession`), and outcome polling (`CompleteReadWithDetails` / `poll_stats()`). | **Pool resharding ("asymmetric TP")** (`PoolReshardPush`, `PoolReshardRegisterRecv`, `ReshardSendSession` / `ReshardReceiveSession` in `reshard_{send,receive}_session.{h,cc}`, `active_pool_reshard_{sends,recvs}_` polled in `CompleteReadWithDetails`, `pool_reshard*`), **`RaidenController`** (`raiden_controller.*`, `Controller/ReadRemote.lean`), and **`kv_cache_store` / `host_offload_backend`**. |
| **2. Upper boundary (External Serving Engine: vLLM / SGLang ↔ `tpu-sync` API)** | **`tpu-sync` API & Engine Caller Contract (`Pipeline` A4, `MultiRequest.lean`; the other direction in `Caller.lean`)**: `NotifyForRead`, `StartRead`, and `CompleteReadWithDetails` (`done_sending`, `done_recving`, `failed_recving`). `MultiRequest.lean` models when the caller may recycle prefill HBM (`.recyclePrefill`: only after `send.published ≠ none`, backed by `PrefillHbmSafe`) or read/recycle decode HBM (`.nextRequest`: only after `recv.published ≠ none`, backed by `DecodeHbmSafe`), and detects premature HBM recycling via `wroteReleased`. `Caller.lean` models what the engine must do *with* a publication, for the production caller pair below: the worker-side connector as a `Connector` (`onSend`, `onRecv : Bool → Signal`) and the vLLM scheduler's transfer-held block lifecycle (deferred free on abort, `invalid_block_ids` under both `kv_load_failure_policy` values, promotion), and proves `Caller.contract_safe`: a connector that forwards every outcome as `finished_sending` / `finished_recving` and reports a failed receive on the load-failure channel (`Caller.Contract`, which is `base.py:357-393`) never leaks a held block on either node and never lets D decode on unwritten KV; `leakP_absorbing` / `leakD_absorbing` show a missed publication is unrecoverable by any later engine action, which is what makes C1 a leak rather than a delay. Note that `tpu-sync` has **no caller-invoked cancel-read API on the prefill-to-decode path** (the only cancel-like public entry point, `cancel_request_blocks_if_unclaimed` in `tpu_sync/api/torch/reshard_client.py`, is reshard-only and outside boundary 1); sessions cancel only on `tpu-sync`'s internal session deadline (each session's `deadline()`, compared in `CompleteReadWithDetails` for sends and receives) or transport error (a failed incoming push in `hooks.end_incoming_push`), manager shutdown (`~KVCacheManagerWithTransfer`) or plan unregister (`UnregisterActivePlan`). | **External vLLM / SGLang Python orchestration** (outside this repository; e.g. the vLLM `TPUConnector` from `tpu_inference.distributed.tpu_raiden_connector` that `examples/single_host_disagg/prefill.sh` / `decode.sh` configure): bootstrap/proxy servers, scheduler queues, external KV block allocators, and engine-side (Python) timeouts. If an external engine times out a transfer in Python and frees HBM *before* `tpu-sync`'s `poll_stats()` publishes settlement, it violates `Pipeline` A4 (`wroteReleased` in `MultiRequest.lean`: in-flight D2H/H2D DMA can read or overwrite recycled HBM). **Checked 2026-10-20 for the production caller pair** tpu-inference `tpu_raiden_connector.py` @ `7ed46a6` on vLLM `6185d73`: the scheduler frees transfer-held blocks only on the connector's `finished_sending`/`finished_recving` report (`scheduler.py:2075-2092, 2466-2474`), defers the free on abort of a `WAITING_FOR_REMOTE_KVS` request (`scheduler.py:2063-2068`), and the connector reports only what `poll_stats()` has settled — so A4 holds by reading. The same reading found that failures are never reported at all, which leaks the blocks instead (finding C1; in Lean `Caller.trace_c1_p`, `trace_c1_d_abort_after`, `trace_c1_d_abort_before`, with `connectorCurrent`). What `Caller.lean` leaves out (its B1–B3): the multi-worker `KVOutputAggregator`, partial-prefix load failures, and preemption / prefix caching / chunked prefill; the scheduler transcription it rests on is checked against the real scheduler by the fork's `findings/tpu_inference_connector_c1_test.py` §4. |
| **3. Lower boundary (Session–Transport Callback Protocol vs. Raw Socket / Wire I/O in `BlockTransport`)** | **Session–transport callbacks, block plans & control-plane worker pool**: (a) incoming push lease (`begin_incoming_push` / `end_incoming_push`, `pushBegin` / `pushEnd`) pinning host staging (`in_flight_ > 0`) across session expiry (`Receive.lean`, `Pipeline.lean`); (b) callback ordering `OnLayerReceived` (`h2dBegin l`) before `OnBlockShardsReceived` (`netAccount`, `Receive` A4); (c) within-layer block-index gather, dual-permutation `BuildLoadCopyPlan` sorting (`remote_order` / `local_order`), and contiguous-run DMA coalescing (`BuildCoalescedCopySpec`) in `BlockOrdering.lean`; and (d) control-plane handshake worker-pool occupancy (`TcpControlPlaneBackend::SendPullRequestBlocking` vs. `GrpcControlPlaneBackend::SendPullRequest`) in `PeerIsolation.lean`. | **Raw socket I/O, wire framing & internal `BlockTransport::layer_progress_`**: Per-stream completion accounting inside `BlockTransport::CompleteIncomingPush` (`layer_progress_` keyed by `{uuid, layer}`; per-sender `sender_streams`; `on_layer_received_called`) sits below **`Receive` A1** (fires `OnLayerReceived(l)` at most once when layer `l` completes), and the shard mask a stream carries (`ShardsFromMask` in `HandleIncomingPush`) below **`Receive` A4**. Raw TCP socket loops (Peregrine `ReadExact`/`ReadVExact`/`WriteExact` with `timeout_ms`), per-read socket timeouts (`handshake_read_timeout_ms` / `payload_read_timeout_ms` / `ack_write_timeout_ms`, read from the environment in `ReadSocketTimeoutsFromEnv`), wire headers, byte-length checks, TCP connection pooling, and raw pointer `memcpy` in `tpu_sync/transport/block_transport.cc` are collapsed into atomic step transitions (`land l`, `h2hDone l ok`, `cancel` + `pushEnd`). Inspect `block_transport.cc` directly for raw socket/wire behavior and cite `Receive` A1 & A4 as the model boundary. |

## Boundary assumptions (`A1`..`An`): discharged vs. external contracts

Every module documents its numbered assumptions (`Receive` A1–A4, `Send` A1–A7,
`Pipeline` A1–A4). When answering questions, distinguish assumptions that are
**discharged by another Lean module**, **enforced directly by C++ control flow**,
or **external caller/transport contracts**:

| Assumption | What it states & C++ location | Status |
|---|---|---|
| **Pipeline A4 (Engine caller contract)** | Decode reads destination HBM only after `poll_stats()` reports `done_recving` (each failed request also carries `TransferDetails` — status code, failed phase, peer, elapsed — unmodelled except the phase, see `Send.phase` / `Recv.phase`); prefill frees/reuses source HBM for a registered transfer only after `poll_stats()` reports that transfer settled (`done_sending` or `failed_recving` in `CompleteReadWithDetails`). If a caller registers multiple chunk reads, it must wait for every registered transfer ID to settle before freeing the corresponding source pages. | **External caller contract** (enforced in `MultiRequest.lean` as the guard on `.recyclePrefill` and `.nextRequest`) |
| **Receive A4 / Pipeline A3 (Transport ordering & single sender per layer)** | For the request that completes a layer, `HandleIncomingPush` (dispatched from `HandleCustomRequest`) calls `CompleteIncomingPush` → `OnLayerReceived` before `OnBlockShardsReceived` on the same thread, and `ExecuteLayerH2d` pushes the future into `h2d_futures_` (`h2d_futures_.push_back(future)`) before returning. The receiver's per-shard counters in `RecordBlockShardsReceivedLocked` can only all reach `total_blocks_ * num_layers` once every stream has reported, so `network_completed_` is set after every layer's dispatch. Readiness soundness (`IsReadyToComplete`) depends on this ordering (refuted without it by mutant `Recv.netAccountUnordered`). | **Ordering: C++ transport contract** (`HandleIncomingPush` / `CompleteIncomingPush`). **Coarsening: discharged in Lean** (`Transport.lean`, `NetworkSound`: the block target is reached only after every layer was dispatched) under `Transport` A4 — every sender sends at most the streams it declared per layer, for the life of the receive. Without that assumption one extra stream on the chunk-count contract reaches the target with a layer never received (`trace_dup_chunk_publishes_missing_layer`). |
| **Receive A1 (One H2D dispatch per layer)** | `BlockTransport::CompleteIncomingPush` fires `OnLayerReceived` once per layer (`on_layer_received_called`), so `ExecuteLayerH2d` is entered at most `numLayers` times (`issued + pending < numLayers`). | **Discharged in Lean** (`Transport.lean`, `OnceDispatched`) under `Transport` A4 (honest senders), A2 (the contract a layer runs under is the one its first stream latched — assumed stable because the `StartRead` path has no plan and `RegisterActivePlan` publishes `base_->RegisterActivePlan` after seating the session under `if (hbm_receiver)`, with the sender's start ordered after that by the controller) and `Cfg.WF.chunkSingle` (the chunk-count contract is single-sender: `StartRead` pulls from `remote_descriptors[0].endpoint`, and a plan with several `shard_push_schedules` selects the sender-declared contract in `KVCacheManagerBase::ExpectedPushSenders`). The latch is erased once `all_layers_called` holds in `CompleteIncomingPush` and `ExecuteLayerH2d` has no latch of its own, so a later stream for a live receive dispatches the layer again on either contract (`trace_dup_after_retirement`); a chunk-count receive with two senders does so even with honest senders (`trace_chunk_two_senders`). |
| **Receive A2 (Session registration)** | External `ReleaseStaging()` is called only on registration failure: in `RegisterActivePlan` and `StartRead` when `EmplaceRecvSessionLocked` rejects the session (never seated); in `RegisterActivePlan` when `base_->RegisterActivePlan` fails (called under `plan_lifecycle_mu_` after the session was seated under `if (hbm_receiver)`), in which case the `if (!registered.ok())` cleanup `mu_` critical section calls `ReleaseStaging()` and `active_recv_sessions_.erase(recv)` together before the plan is published. | **Discharged / C++ init discipline** (registration table modelled in `UuidTable.lean`) |
| **Receive A3 / Send A4 (No double end)** | Each `in_flight_` op ends at most once (one future callback per issued copy/push, one `end_incoming_push` per `begin_incoming_push`). | **C++ callback / RAII discipline** |
| **Send A1 (At-most-once `StartPush`)** | `StartPush` runs at most once per send session, after `NotifyForRead` registration and `ValidateAndBeginPull` (`pull_started_` atomic claim). | **Discharged in Lean** (`Send.PullClaimed`, `Pipeline.HandshakeSafe`, `BlockOrdering.validateRequestedBlocks_iff`) |
| **Send A2 & A6 (Sequential D2H loop & `SendNextLayer(0)` fold)** | `StartPush` issues D2H copies on a single thread and calls `SendNextLayer(0)` immediately after the last layer. | **C++ control-flow structure** |
| **Send A3 (Layer-counter abstraction in `Send.lean`)** | `Send.lean` counts copies/pushes without layer indices (`SendNextLayer` chains in order `0, 1, …`). `Pipeline.lean` does **not** inherit A3: every memory-touching event in `Pipeline.lean` is explicitly layer-indexed (`d2hReady l`, `h2hDone l`, `land l`, `h2dBegin l`, `h2dIssue l`, `h2dReady l`). | **Discharged in Lean** (`Pipeline.lean`) |
| **Send A5 (No consumer `Ack`)** | The client-side `SendAck` (`GrpcControlPlaneBackend::SendAck`, `TcpControlPlaneBackend::SendAck`) has no non-test caller; the server-side handler `OnAck → HandleAck → AckSend → Finish()` in `KVCacheManagerWithTransfer` is wired but never triggered in-repo, so it is excluded. | **Dead path** |
| **Send A7 (Connection-release window)** | Under `TPU_RAIDEN_DATA_CONN_REUSE=per_transfer` (default `pooled` never takes the branch) the last `EndSendOp` of a draining send drops `mu_` to close idle data connections (`CloseDataConnectionsForTransfer`) before `EndSendOpLocked`. In the window `in_flight_ == 1`, `draining_` and `!done_` are fixed (no new op, `FinishLocked` returns on `if (draining_) return;`, the poll sees `Done() == false`), so the model's atomic `endOp` is exact; the window only delays `done_`. | **Simulation soundness argument** (`Send.lean` A7) |
| **Pipeline A1 (Whole-layer cell abstraction in `Pipeline.lean`)** | `Pipeline.lean` models each layer's payload as one `Cell`. `BlockOrdering.lean` refines each layer into a block-indexed array (`List BlockCell`), models `ValidateRequestedBlocksLocked`, `BuildCoalescedCopySpec`, and `BuildLoadCopyPlan`, and proves a lockstep forward simulation (`BlockPipeline.step_pipe`) over `Pipeline.step`. | **Discharged in Lean** (`BlockOrdering.lean`) |
| **Pipeline A2 (Delivery ordered after push callback)** | `Pipeline.lean` models `h2hDone l true` before `land l`; in C++ the receiver lands the layer payload (`ForEachPayload` loop in `HandleIncomingPush`) before sending the ack (`WriteExact(client_fd, &ack, 1, ...)`) that triggers the sender's callback. Sound because `prefillStaging[l]` is invariant throughout `[h2hIssue, h2hDone]` while `in_flight_ > 0` pins staging. Leaves out the trace where a layer lands but the ack fails (safe by the same staging pin). | **Simulation soundness argument** (`Pipeline.lean` A2) |
