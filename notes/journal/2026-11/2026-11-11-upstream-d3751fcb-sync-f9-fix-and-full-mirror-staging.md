# Upstream `d3751fcb` sync: `LookupAndClaim` TTL refresh (F9 closed), full-mirror in-place reshard staging, and opt-in Peregrine `RecvHooks`

Canonical sync facts: `../../upstream-rechecks.md` row 2026-11-11 and `findings/README.md` §History (2026-11-11). This entry records only the delta in model and boundary understanding.

[OBS 2026-11-11] **`RequestBlockRegistry::LookupAndClaim` now refreshes claimed producer rows' TTLs (`63c6447c`, F9 closed).** `LookupAndClaim` collects `claimed_rows` during unit validation and sets `registration.expires_at = now + ttl_s_` on every claimed `request_blocks_` row alongside `claimed_[lifecycle_key] = now + ttl_s_`, while failed claims return before the loop and leave partial registrations on their original TTL (`ReshardStackTest.ClaimRefreshesRegistrationTtlForSiblingStageAndCompletion`, `FailedClaimDoesNotRefreshPartialRegistrationTtl`). Under `docs/conventions.md` §"Describe the code as it is", `Registry.lean`'s unrefreshed-row trace (`s.purgeExpiredRequestBlocks` on a claimed state) is now counterfactual mutant `mutant_split_ttl_purges_request_blocks_while_claim_active` witnessing `ClaimOwnersConsistent`, paired with `trace_claim_refreshes_registration_ttl_while_failed_claim_does_not` for the shipping behavior.

[OBS 2026-11-11] **Full-mirror in-place reshard staging (`47e9f200`) trades F15's slot wait on unbounded mirrors for an aliased-storage host-buffer clobber.** `ReshardReceiveSession` and `ReshardSendSession` now gate `StagingLayerManager` on `HostLayersBounded()` (`num_host_layers() < num_layers()`) and return `StaticHostLayer(pool_idx) = pool->storage_index` when `!HostLayersBounded()` (`num_staging_layers` unset). That makes the Lean `Reshard/{Send,Receive,Pipeline}` models match the default full-mirror path directly whenever concurrent pools occupy disjoint host bytes (separate `storage_index`, disjoint sub-block regions such as `conv` + `ssm`, or disjoint block IDs), while keeping F15's rank-vs-slot deadlock open whenever `num_staging_layers < num_layers`. However, on the aliased-page shape `order_rank` exists for — a coarse rank-0 pool (`fa`) and a rank-1 pool (`state` / `swa`) sharing `storage_index` and `dst_device_block_ids` with overlapping region bytes — `StaticHostLayer` maps both pools to the same `layers_[storage_index]` buffer: when rank 1 arrives on the wire first, its bytes stage into `layers_[storage_index]` and its H2D waits behind rank 0, and rank 0's subsequent push overwrites those staged host bytes in place before rank 1's H2D runs (realizing the hazard noted when F15 was filed on 2026-11-02; reproduced in `findings/reshard_recv_staging_slot_rank_deadlock_bughunt_test.cc`).

[OBS 2026-11-11] **Opt-in Peregrine `RecvHooks` (`e3d1c848`) wire `ResolveRecvBuffer` / `OnRecvComplete` for `kBlockPushExplicit`.** `BlockTransport`'s constructor now passes `RecvHooks{.on_post_complete = OnRecvComplete, .resolve_addr = ResolveRecvBuffer}` to `PeregrineTransportAdapter::Create` when `config_.uses_peregrine()` (`TPU_RAIDEN_ENABLE_PEREGRINE`, default off), and `PostExplicitPush` sends `raddr = nullptr` so every request resolves through `ResolveRecvBuffer`. That avoids the unleased sender-`raddr` case on explicit pushes, while the `RejectPost` lock-gap `PostLease` leak (`~KVCacheManagerWithTransfer` deadlock) and `PostKeyOf` `{remote_id, local_id, shard_mask}` collision parked at `00e946e3` are now reachable on opt-in `TPU_RAIDEN_ENABLE_PEREGRINE` traffic.
