# Upstream `00e946e3` sync: manager-owned session bookkeeping, host-memory transfers, and what changed in the models

Canonical sync facts: `../../upstream-rechecks.md` row 2026-11-09 and `findings/README.md` §History (2026-11-09). This entry records only the delta in model understanding.

[OBS 2026-11-09] **A failed pull reply no longer flips a settled receive.** `TransferReceiveSession::Start`'s `on_response` lambda now finishes only `if (!pull_status.ok() && !self->draining_)` (`32568d35`, with the comment that a receive settled before a slow control reply "keeps its verdict" — a host destination with no H2D step makes the data outrunning the reply likely). That is the `Receive/Coverage.lean` open question ("can a reply fail after its data landed?") answered by the C++, and F14's only production-reachable prefill-to-decode case (3) closed. `Recv.pullReply false` gained the `draining` guard (`if ok ∨ draining then life else life.finishLocked false`); the old order is mutant G13 and *survives* — safety never depended on which verdict wins, only the publication did. Receive branches 37 → 35, uncovered 13 → 11; the ripple into `Pipeline/Progress.lean` was one witness state (`s.recv.life.endOpLocked` instead of `(finishLocked false).endOpLocked`). `FinishLocked` itself still records the error before `if (draining_) return;` on both receivers, so F14's `EndIncomingPush`, `UnregisterActivePlan`, destructor and deadline-sweep-race cases stand.

[OBS 2026-11-09] **Host-memory transfers are a different data path, not a different protocol — kept as a boundary.** `BlockLocation::kHost` on the producer (`TransferSendSession::StartPush`: no staging, `d2h_layer_futures_` pre-resolved OK, straight to `SendNextLayer(0)`) is the device model after the prefix `beginPull, start, (d2hBegin, d2hIssue true, d2hReady, d2hEnd)^n` (`Send.trace_host_source_prefix`); the only over-approximation is `wake false`, which a host send never produces. On the consumer (`TransferReceiveSession::SettleHostLayer`) a layer report increments `num_completed_layers_` with no op and no future, and the last one settles the receive *inside the push lease* via `RecordNetworkCompleteLocked(true)` → `FinishLocked()` — the arm the notes called dead is dead only on the device path. A `Cfg` flag was rejected on both sides: on the receive it would violate `CountersOrdered` (`issued = ready = retired = 0` while `completed` climbs), on the send it would add a `start` branch that `Pipeline` / `MultiRequest` build on, for an exact simulation argument. `CheckHostMemoryTransferSupported` (`num_host_layers() == num_layers()`, `!staging_allocator_->LeasesHostBlocks()`) keeps host transfers away from `LayerStaging` and `PeerIsolation`, and a kHost `StartRead` leases no staging slot at all (outside F5's pool). Candidate follow-up model: a `Recv` with the H2D events replaced by one `hostLayerSettle`.

[OBS 2026-11-09] **The sub-plan chain is now one req_id-keyed table shared by both roles, and it reports directly when it has no entry.** `25f7d8a7` merged `recv_chains_` / `send_chains_` into `sub_plan_chains_` with `SubPlanChainProgress{sub_sessions, completed, failed, last_activity, anchored}`; `NoteSubPlanRegisteredLocked(req_id, session, index, count)` *erases* the entry on `count <= 1` (the old code ignored single plans) and re-anchors fresh on index 0; `RecordPoolReshardTerminalLocked(is_recv, req_id, uuid, session, status)` finds the sub-plan by `std::find` on the session pointer and, with no entry (or an unanchored entry that does not hold the session), inserts the request's terminal directly. The `SubPlanChain` worker model was rewritten on `ChainProgress{present, subSessions, completed, failed, anchored}`; `reachable_worker_safe` now needs three assumptions the old code did not: A5 the deadline arm runs before the sweep in the same `CompleteReadWithDetails` (so a stalled chain's open sessions are failed before the entry is erased), A6 no single-plan registration arrives while a sub-plan of the req_id is seated, A7 one session per slot. Each has a mutant (`mutant_no_deadline_arm_reports_done_after_sweep`, `mutant_single_plan_registration_erases_live_chain`, `mutant_slot_overwrite_reports_stray_done`). Whether A6/A7 are facts about the callers or latent defects is not yet established — parked as candidate hazards in `../../loose-ends/parked.md`.

[OBS 2026-11-09] **Push-session retirement no longer clears the table.** `CompleteIncomingPush` sets `done_` without `layer_progress_.clear()`; `GetOrCreatePushSession` hands out the map's session only while `!IsDone() || HasAdmittedPosts()` and otherwise seats a fresh one, and `HandleIncomingPush` ends with `DeletePushSession(session)`. `Transport.retire` (`entry := none`) now reads as "the fresh session a later stream gets"; a concurrent stream that already holds the retired session finds the latched entry and cannot re-dispatch, so the model admits one dispatch the C++ refuses — an over-approximation on the dishonest side only (A4). The chunk-count contract is still `completed_chunks == expected_chunks` with no over-count rejection (R-B unchanged).

[OBS 2026-11-09] **Upstream's test rewrite closed most reshard session gaps without us.** `FakeD2hBase` / `FakeH2dBase` (promise-backed `D2hPoolBlocks` / `H2dPoolBlocks`, now virtual) replaced the `*TestPeer` seams; Reshard Send paired 7 → 10 / 26 and Reshard Receive 4 → 13 / 36, and the `Gap.futureStub` class became `copyError` / `heldUpload` because the fakes exist now. `5835b975`'s lifecycle tests left `Registry/Coverage` (25/25, all 7 refusals) and `Coordinator/Coverage` (14/14) with no test gaps — the `coverage_gap_reshard_control.patch` is now largely redundant and no longer applies. Lost pairings: `FinishAfterLastPushFinalizingPreservesOkStatus` (deleted; `trace_finish_after_last_push` is model-only again).

[OBS 2026-11-09] **Process.** Six workers on disjoint files (W1 Receive/UuidTable/PeerIsolation/Session, W2 Pipeline/LayerStaging/MultiRequest/BlockOrdering, W3 Send/Transport/Caller, W4a Reshard sessions, W4b Reshard control/chain, W5 docs/agents) plus a findings re-check (W6, which rebuilt and re-ran F15–F17 on OSS Bazel: cold build ~16 min, one network fetch for peregrine 0.1.17). The one cross-module semantic change (`pullReply`) was broadcast within minutes of W1 finding it; the docs worker idled until every model worker sent it final counts directly. Brief errors worth remembering: `SessionEntry` has three fields (`role`), and there is no `RegisterSessionLocked` symbol — `NotifyForRead` `try_emplace`s inline. Upstream's `formal_verification/` copy (`42dda54` export + `4ecfc893`) conflicts on every shared file at each sync; resolve to the fork's tree with `git checkout HEAD -- tpu_sync/formal_verification` during the merge.
