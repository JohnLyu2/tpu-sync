# Upstream `56a0269d` sync: the `TransferSession` interface and what it changed in the models

Canonical sync facts: `../../upstream-rechecks.md` row 2026-11-02 and `findings/README.md` §History (2026-11-02). This entry records only the delta in model understanding.

[OBS 2026-11-02] **A second `network_completed_` setter on the socket path.** `TransferReceiveSession::ExecuteLayerH2d` now ends with a third `mu_` scope: `dispatched_layers_.insert(layer_idx)`, and `network_completed_ = true` once the set holds every layer and the receive is neither done nor draining (`11a439d4` moved the Peregrine-only `OnRecvNetworkComplete` of `86d4506` into the session for every transport). Modelled as `Recv.netIssued`, set by `h2dIssue true` on the last layer (A1 makes the set's size `issued`). Consequences: `ReadinessSound` now holds directly for that setter (`Inv.netIssued_issued`) without the A4 transport-ordering argument, which still backs the block-accounting setter; `RecordNetworkCompleteLocked`'s `FinishLocked` arm is now dead even more plainly (`netAccount`'s finish arm requires `netIssued = false`, impossible once every layer was issued); the third scope is folded into `h2dIssue true` because a `cancel`/`h2dDone` landing before it leaves `network_completed_` false where nothing modelled reads it once draining (only `CurrentPhaseLocked`). Coverage numbers for `Receive` did not move from the change itself (37 branches), only from the new upstream tests.

[OBS 2026-11-02] **One `sessions_` map changes the uuid-reuse rules.** With sends, receives and reshard sessions in one `flat_hash_map`, `NotifyForRead`'s `try_emplace` is refused by *any* seated session under the uuid — including a settled receive the poll has not yet retired — and throws; `StartRead` / `RegisterRecv` retire a settled send inline (publishing it) and are refused by a live one (`StartRead` files the request in `failed_recving_` with `AlreadyExists` unless the incumbent is a receive with the same `req_id`). `EmplaceRecvSessionLocked` and `RegisterActivePlan` first `Finish()` a non-draining incumbent whose `IsReadyToComplete()` holds (test `RegisterRecvFinishesAReadyIncumbentBeforeReplacingIt`), which `StartRead` does not (`RedeliveredStartReadLeavesAReadyReceiveToCompleteRead`); `UuidTable.active_recv_preserved` therefore needs `0 < inFlight ∨ ¬ isReadyToComplete`. Upstream's own orchestrated-transfer tests switched to two managers because a send and a receive can no longer share one uuid in one process.

[OBS 2026-11-02] **Reshard plan lifetime is `!done`.** `plan_unregistered_`, `unregister_on_settle_`, `RegisterActivePlanDirect` and the manager's unregister hooks are gone; each session owns its `TransferPlan` and `plan()` is `nullopt` iff `Done()`. The `PlanIntegrity` properties and `planUnregistered` ghosts had nothing left to say and were retired (plan visibility is covered by `SettleSafe` / `NoRetiredCallback`); the early-unregister behaviour of F10 can no longer be expressed, so F10 is closed by `1523b07d` rather than kept as a mutant. `PoolReshardRegisterRecv` now claims the uuid in `pending_pool_reshard_recvs_` before `Create`, and `CompleteReadWithDetails` skips `ReleasePoolStagingLeases` for a uuid that is pending or re-seated — the in-flight guard `PoolStaging.RegState.step` already had.

[OBS 2026-11-02] **Two reshard `step` changes.** `ReshardSendSession::Finish` returns at `if (done_ || finalizing_)` before recording `status_` (`1523b07d`), so `Send.cancel` is `finishOnceLocked false` (the sender's "first `Finish` wins" of the prefill path); the receivers' `FinishLocked` still records first, so F14 stays open there. `ReshardSendSession::Start` (`f9f66e7c`) fails synchronously on `ValidatePushPreconditions` or a thread-start error — `Send.Ev.startFail`, killed-mutant `startFailWithoutRecord` (`ActiveOrDraining`).

[OBS 2026-11-02] **F11's fix is the model's candidate.** `c0e8e686`'s `process_completion` in `NumaAwareKVCacheManager::CompleteReadRaw` is line for line `NumaBarrier.numaProcessSettled` (`s + r + f >= expected`; `f > 0` first; then `r`, then `s`; else failed; erase all four maps). No theorem changed; `NumaPolicy.settledCounts` is now documented as shipping and `eagerFailSet` as the mutant, and the five replacement wrapper tests replay on `settledCounts`.

[OBS 2026-11-02] **Bounded host layer staging on reshard sessions deadlocks with the rank-wave gate — F15.** Both reshard sessions lease one `StagingLayerManager` slot per *pool index* from `num_host_layers()` slots, even on the full mirror (no `NotFound` bypass as on `TransferReceiveSession`); the receive holds a pool's slot from its first push chunk until its H2D completes, and a rank-1 pool's H2D waits for every rank-0 pool. When several tags' pools share a storage (the aliased-page layout `order_rank` exists for; fewer slots still under `num_staging_layers`), transferred pools outnumber `num_host_layers()`: even one sender's concurrent per-pool pushes + rank-blind `StagingLayerManager::Acquire` hand-off can leave every slot held by gated rank-1 pools while a rank-0 pool has received no first chunk, closing the hold-and-wait cycle until `DEADLINE_EXCEEDED` after `timeout_s_` (see `findings/README.md` §F15; filed as bug 13 in `findings/filed_bugs.md`). Confirmed on CPU the same day (`findings/reshard_recv_staging_slot_rank_deadlock_bughunt_test.cc`, 1 control + 1 failing case; the test issues no H2D, because `CopyPoolBlocks` now calls `GetOnDeviceSizeInBytes()` on a default-constructed `RaidenBufferHandle` and segfaults without a `RawBuffer` test subclass). Lesson for the scope-out decision: the composition of a new resource (slot) with an old ordering constraint (rank wave) is exactly what the Lean model exists to catch (`reachable_can_settle` would fail); scoping out was right for the sync's budget but the boundary paragraph must state the exact progress precondition (`num_host_layers >=` active pools or single-rank) and be followed by a reachability read like this one. Parked: model it after the owners pick a fix shape.

The `llvm-cov` numbers in both docs were not re-measured.
