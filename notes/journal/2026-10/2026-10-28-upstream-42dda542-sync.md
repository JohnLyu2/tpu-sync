# Upstream `42dda542` sync: `StartPush` early `SendNextLayer(0)` chain and C1 upstream fix

Canonical sync facts: `../../upstream-rechecks.md` row 2026-10-28 (`c9bc124` → `42dda54`) and `findings/README.md` §History (2026-10-28). This entry records only the delta in model understanding and guard semantics.

[OBS 2026-10-28] **Why `1b78685f` flips `Send/Guards.lean` S9 (`draining_ &&` in `EndSendOpLocked`) from killed to surviving.** Before `1b78685f`, `TransferSendSession::StartPush` armed `SendNextLayer(0)` only after the last layer's `D2hSyncDispatch` loop completed, so an early layer's D2H copy finishing (`d2hReady` + `d2hEnd`) while the loop was between iterations transiently dropped `in_flight_` to `0` on an active, non-draining session; dropping `draining_ &&` in `EndSendOpLocked` (`endOpEager`) therefore settled the session mid-loop and violated `Safe`. In `1b78685f`, `StartPush` pre-creates per-layer `d2h_promises` / `d2h_layer_futures_` and calls `SendNextLayer(0)` *before* the D2H loop. Because each layer `l < total_layers - 1` arms `SendNextLayer(l + 1)` inside the pool task before releasing layer `l`'s op, and the final layer's H2H callback calls `FinishLocked(OkStatus())` before `EndSendOpLocked()`, the H2H chain carries an unbroken `in_flight_ > 0` baton from `start` until `draining_ == true`. Consequently, `in_flight_ == 0` is unreachable while `!draining_` once `StartPush` has armed the chain (`S9` now survives both `SafeCore` and `Safe`).

[OBS 2026-10-28] **Why `fail_unissued_layers` is load-bearing (`S13`) and weakens `woken_d2hReady` to issued layers.** Pre-creating all `total_layers` futures means `SendNextLayer(k)` can wait on a layer `k >= d2hIssued` whose `D2hSyncDispatch` never ran because `StartPush` exited early (cancellation, staging-layer acquisition error, or dispatch failure). Without `absl::Cleanup fail_unissued_layers` resolving promises `next_layer .. total_layers - 1` (`Send.stepWithoutFailUnissued`), `SendNextLayer(k)`'s `OnReady` never fires (`queued > woken`) and `in_flight_` leaks forever (`Send.trace_without_fail_unissued_leaks`). With `fail_unissued_layers`, `wake false` fires on `woken >= d2hIssued` once `draining && !d2hPending`, so `Send.Inv` adds `woken_issued : d2hIssued < woken → draining ∧ ¬d2hPending` and `Pipeline.Inv.woken_d2hReady` guards on `l < woken → l < d2hIssued → d2hReadyL[l]? = some true` (which still suffices for `h2hDone true`, since `h2hIssued ≤ d2hReady ≤ d2hIssued`).

[OBS 2026-10-28] **Failed `D2hSyncDispatch` now calls `EndSendOp()` rather than `EndSendOpLocked()`.** Because `SendNextLayer(0)` runs concurrently with the D2H loop, earlier layers may already have opened data connections and completed their H2H pushes by the time layer `l`'s `D2hSyncDispatch` fails; `StartPush`'s `!future.ok()` cleanup can therefore retire the session's *last* in-flight op and must go through `EndSendOp()` so `kPerTransfer` closes idle peer connections outside `mu_` (`Send` A7).

[OBS 2026-10-28] **Caller C1 upstream fix vs. `Caller.lean` and `Caller/MultiWorker.lean`.** `vllm-project/vllm` `e7bb7e2f` (`KVConnectorTransferResults`, `Scheduler._handle_failed_recving`, and `KVOutputAggregator._failed_recving_pending`) plus `vllm-project/tpu-inference` PR `#3918` (`f366ef523`) implement the single-worker two-channel contract (`connectorFixed`) and a multi-worker request-level latch (`_failed_recving_pending & finished_recving`, currently argued via **M1** in `Caller/MultiWorker.lean` rather than a separate `mwStep` mode). Note that PR `#3918` does *not* override `get_block_ids_with_load_errors`, and its `get_finished()` wrapper returns `(results.finished_sending, results.finished_recving)` — so on a pre-`e7bb7e2f` vLLM such as `6185d73` (which calls `get_finished()` rather than `get_transfer_results()`), it would drop `failed_recving` and behave as `connectorNaive` (`trace_naive_decodes`).
