# Pool-reshard transfer: model and results

The reference map from the pool-addressed resharding KV-cache transfer C++ to
its Lean models under `TpuSyncVerify/Transfer/Reshard/`, sibling to
[prefill_decode.md](prefill_decode.md). Line
spans in the routing index below are resolved from the C++ source tree by
`python3 tpu_sync/formal_verification/tools/resolve_anchors.py`.

Pool resharding transfers KV cache across heterogeneous parallelism topologies
(`TP` / `PCP`) and multi-pool hybrid-model device arenas:

1. **Rank-ordered pool H2D waves on aliased device pages**
   (`ReshardReceiveSession`, `reshard_receive_session.{h,cc}`): pools carry a
   `rank` (e.g. full-attention at rank 0, state classes at rank 1 on shared
   hybrid-model arena pages), and a pool's H2D copy may launch only after every
   expected pool of strictly lower rank has *completed* its H2D callback
   (`CollectEligiblePoolH2dsLocked`), even when higher-rank pools finish
   arriving over the network first.
2. **Multi-sender sub-block fan-in and per-(pool, peer) push slots**
   (`ReshardSendSession`, `reshard_send_session.{h,cc}`;
   `CountPoolReshardSendSlots`, `pool_reshard_send_slots.{h,cc}`;
   `BlockTransport::HandleIncomingPush` plan-declared progress): `N` senders
   push disjoint sub-block byte slices into one receiver pool; the transport
   counts completed streams per `(uuid, pool)` against `expected_pushes` before
   firing `OnPoolReceived(pool_idx)` once (`BlockTransport::CompleteIncomingPush`).
3. **Bounded per-UUID pool host-staging leases** (`PoolStagingStorage`,
   `KVCacheManagerBase::AcquirePoolStagingLease`,
   `KVCacheManagerBase::ReleasePoolStagingLeases`,
   `KVCacheManagerBase::GetBlockChunks`):
   both sessions lease bounded staging slots per `(storage_idx, uuid)` up front
   and release them by `uuid` on settle or destruction.
4. **Two-phase Arm-then-Dispatch coordination and block registry claims**
   (`ReshardCoordinator`, `reshard_coordinator.{h,cc}`; `RequestBlockRegistry`,
   `request_block_registry.{h,cc}`): the coordinator claims producer blocks,
   arms every destination receiver (`PoolReshardRegisterRecv`) and collects
   their pool host addresses before dispatching any sender (`PoolReshardPush`),
   and retires producer blocks only when every source unit votes `Complete`.

Each `trace_*` theorem's docstring names the upstream C++ test it replays —
covering all 16 tests in `reshard_receive_session_test.cc`, 6 of 9 in
`reshard_send_session_test.cc` (the remaining 3 `TPU_RAIDEN_DATA_CONN_REUSE`
mode-toggle tests are noted under `Send` A4), all 19 in
`kv_cache_manager_with_transfer_pool_reshard_test.cc` (including
`FailedIncomingPushReleasesStagingLeaseBeforeDeadline`), all 6 in
`pool_staging_test.cc`, all 4 in `pool_reshard_planner_streams_test.cc`, and 11
registry, coordinator, and `DefaultTransferStreams` tests in
`reshard_service_test.cc`.

## Modules

Each module's header docstring carries its state table, event table,
assumptions, and properties; this is the structural map. Higher modules compose
the lower `step` functions directly: `Pipeline` composes `Send.step` and
`Recv.step` with per-pool stream counters, five pool-indexed memories (`srcHbm`,
`srcStaging`, `wire`, `dstStaging`, `dstHbm`), aliased-page overwrite
(`writePoolHbm`), and the coordinator's Arm-then-Dispatch barrier; `Coverage`
refines `Pipeline`'s scalar stream counter into sub-block byte intervals via a
lockstep forward simulation (`CoveragePipeline.step_pipe`); `Coordinator`
composes `Registry.step` with multi-destination receiver arming and
`PoolStagingLease` lifecycles.

## Shipping C++ vs. modelled design alternatives

Four modules parameterize both the **current C++ behavior** and a
**modelled alternative**, so that a guard's role is shown by what breaks
without it (`PushEndPolicy`, `RegistrationPolicy`) or a candidate fix for an
open observation is proved sufficient (`UnregisterPolicy`, `CleanupPolicy`;
`R2a`/`R2b`, `R6` below):

| Module | Parameter | Baseline C++ behavior | Modelled alternative |
|---|---|---|---|
| `Reshard/Receive.lean` | `PushEndPolicy` | **`PushEndPolicy.finishOnError`**: `hooks.end_incoming_push` (`KVCacheManagerWithTransfer::InitializeBaseHooks`) calls `reshard_session->Finish(status)` before `EndRecvOp()` when `!status.ok()` (matching the `TransferReceiveSession` branch), so a failed push drains and releases staging at once (`trace_r1_failed_incoming_push`; regression test `PoolReshardRecvTest.FailedIncomingPushReleasesStagingLeaseBeforeDeadline`). | **`PushEndPolicy.endOpOnly`** (mutant): calls `EndRecvOp()` without checking `status.ok()`, so after a mid-transfer push failure the receiver stays `!IsDraining() && !Done()`, pinning its `PoolStagingLease` and active plan until `timeout_s_` (`trace_r1_failed_incoming_push`). `Recv.reachable_safe` holds under both. |
| `Reshard/Send.lean` | `UnregisterPolicy` | **`UnregisterPolicy.shipping`**: `ReshardSendSession::RecordPushCompletion` calls `UnregisterActivePlan` as soon as `finalizing_` is latched on the first error, even while sibling pools/peers still have `in_flight_ > 1` (`trace_early_unregister_on_error_vs_onSettle`), exposing concurrent `StartPoolPush` calls to `GetBlockChunks` after plan removal (`R6`). | **`UnregisterPolicy.onSettle`**: Defers `UnregisterActivePlan` exclusively to `ReshardSendSession::EndOp` on settle (`in_flight_ == 1 && finalizing_`). Proves `planUnregistered = s.life.done` in every reachable state (`reachable_onSettle_plan_iff_done`). |
| `Reshard/PoolStaging.lean` | `RegistrationPolicy` | **`RegistrationPolicy.reserveBeforeLease`**: `ReshardReceiveSession::Create` claims `uuid` via `RegisterActivePlanDirect` before constructing the session and acquiring `PoolStagingStorage` leases. Proves inductively (`reachable_reserveBeforeLease_safe`) that every active session retains its allocated staging slots (`ActiveSessionsHoldLeases`). | **`RegistrationPolicy.leaseBeforeReserve`** (mutant): acquires `st.leases[uuid]` before `RegisterActivePlanDirect`. A rejected duplicate-UUID call destroys its temporary session, whose destructor calls `ReleasePoolStagingLeases(uuid)` and frees the surviving session's physical staging slots (`trace_r5_duplicate_uuid_frees_survivor_lease_and_aliases_slot`). |
| `Reshard/Coordinator.lean` | `CleanupPolicy` | **`CleanupPolicy.shipping`**: `ReshardCoordinator::ExecutePoolReshard` abandons the registry claim on Stage 1 partial-arm failure without disarming already-armed receivers (`trace_r2a_partial_arm_orphans_armed_receiver`), and returns on Stage 2 sender-dispatch failure (`if (!sender_status.ok()) return sender_status`) without disarming receivers or calling `AbandonClaim` (`trace_r2b_dispatch_failure_orphans_receivers_and_claim`). | **`CleanupPolicy.disarmAndAbandonOnFailure`**: Disarms armed destination receivers and calls `AbandonClaim` on both Stage 1 and Stage 2 failures. Proves inductively (`reachable_disarmAndAbandon_no_orphans`) that every reachable `.aborted` state has zero armed receivers, zero held staging leases, and `claimedUnits = none`. |

## Verified properties → theorems

The proved theorems establish three top-level system guarantees across the
data and control planes, supported by per-session and per-component invariants:

| Property | Where proved | Statement |

## System & model boundaries (horizontal, upper, and lower)

The pool-reshard Lean model sits between three explicit boundaries:

| Boundary | In scope / Modelled in Lean | Out of scope / Abstracted at boundary |
|---|---|---|
| **1. Horizontal boundary (Pool Resharding vs. Other Subsystems & Pure Compilers)** | **Pool-addressed KV-cache resharding**: `ReshardReceiveSession`, `ReshardSendSession`, `CountPoolReshardSendSlots`, `DefaultTransferStreams`, `ValidatePlan` / `ValidateReceiverCoverage` output contracts, `PoolStagingStorage` bounded leases, `RequestBlockRegistry`, and `ReshardCoordinator::ExecutePoolReshard`. | **Prefill-to-decode ("symmetric") transfer** ([prefill_decode.md](prefill_decode.md)), **pure planner geometry & transfer-program lowering** (`tpu_sync/kv_cache/reshard/pool_reshard_planner.cc` and `tpu_sync/core/transfer_program_reshard.cc`, which compile topology geometry into `StartTransferRequest` plans validated by `ValidatePlan` / `ValidateReceiverCoverage`), and **`weight_sync/`** model-weight resharding. |
| **2. Upper boundary (Serving Engine & Controller Orchestration ↔ `ReshardCoordinator` / Sessions)** | **`RequestBlockRegistry` & `ReshardCoordinator` two-stage protocol**: producer block registration (`Register`), multi-owner `LookupAndClaim`, `CancelIfUnclaimed` tombstones, Stage 1 destination arming (`PoolReshardRegisterRecv`), Stage 2 sender dispatch (`PoolReshardPush`), per-unit `Complete` voting, and `CompleteReadWithDetails` (`poll_stats()`) outcome publication. | **Disjoint source and destination units (`src_units ∩ dst_units = ∅`)**: `BuildStartTransferForTarget` sets `is_sender = true` when a unit appears in both lists, which `WorkerServiceImpl::StartTransfer` dispatches only to `PoolReshardPush`. Disjointness is treated as a caller/planner precondition. External Python serving-engine scheduling above `ReshardService` is outside this repository. |
| **3. Lower boundary (Plan-Declared Transport Progress & Staging Arena vs. Raw Socket / DMA I/O)** | **Per-(uuid, pool) stream counting, sub-block interval coverage & `PoolStagingStorage` slot maps**: `begin_incoming_push` / `end_incoming_push` op leases, `CompleteIncomingPush` counting completed streams against `expected_pushes` before firing `OnPoolReceived(pool_idx)` once, sub-block byte-interval partition on destination staging (`Coverage.lean`), and per-`(storage_idx, uuid)` slot allocation/release in `PoolStagingStorage` (`PoolStaging.lean`). | **Raw TCP socket loops, wire framing & PJRT DMA execution**: Peregrine `ReadExact`/`WriteExact` loops, TCP connection pooling (`EndOp` per-transfer idle connection release in `ReshardSendSession::EndOp`, Send A4), and raw pointer `memcpy` / PJRT `CopyFromHostToDevice` / `CopyToHostAsync` internals are abstracted into atomic state-machine transitions (`d2hDone`, `landStream`, `h2dIssue`, `h2dDone`). |

## Boundary assumptions (`A1`..`An`): discharged vs. external contracts

Each session module documents its numbered assumptions (`Receive` A1–A4, `Send`
A1–A4):

| Assumption | What it states & C++ symbol | Status |
|---|---|---|
| **Receive A1 (At-most-once `OnPoolReceived` per declared pool)** | `BlockTransport::CompleteIncomingPush` fires `OnPoolReceived(l, uuid)` only when `plan_pushes == expected_chunks`, and `ReshardReceiveSession::RecordPoolReceivedLocked` rejects undeclared or duplicate pool indices. | **Discharged in Lean** (`Pipeline.lean` `StreamAccountingSafe`, `Coverage.lean` `stream_count_matches` & `CoveragePipeline.step_pipe`) |
| **Receive A2 (Registration before visibility)** | `RegisterActivePlanDirect` and `AcquireStagingLeases` (`ReshardReceiveSession::Create`, `ReshardReceiveSession::AcquireStagingLeases`) succeed before the session is inserted into `active_pool_reshard_recvs_` (`KVCacheManagerWithTransfer::PoolReshardRegisterRecv`), rolling back both on failure. | **Discharged in Lean** (`PoolStaging.lean` `reachable_reserveBeforeLease_safe`, `Coordinator.lean` `no_push_before_all_armed`) |
| **Receive A3 / Send A3 (No double end & single `StartPoolPush` lock step)** | Each admitted push and each H2D/D2H op ends at most once; `ReshardSendSession::StartPoolPush`'s two `done_ \|\| finalizing_` checks inspect only immutable plan fields in between and fold into `d2hDone`. | **C++ callback / control-flow discipline** |
| **Receive A4 (Fold of `RecordPool*Locked` with `ExecuteEligiblePoolH2ds` first lock)** | An external `Finish` arriving between unlocking `mu_` after recording a pool (`OnPoolReceived` / `FinishPoolH2d`) and locking `mu_` at the entry of `ReshardReceiveSession::ExecuteEligiblePoolH2ds` is observationally equivalent to arriving either before the entry lock or immediately after releasing `mu_` following `in_flight_ += static_cast<int32_t>(to_launch.size())` (where the per-pool `if (done_ \|\| draining_)` re-check inside the loop aborts each queued pool). | **Simulation soundness argument** (`Receive.lean` A4, `trace_cancel_between_batch_queue_and_issue`) |
| **Send A1 (Non-empty schedule with positive peer counts per active pool)** | `ReshardSendSession::Create` rejects plans with `remaining_pool_peer_pushes <= 0`, and `ReshardSendSession::ExecutePush` skips pools with zero scheduled entries on this sender, matching `CountPoolReshardSendSlots`. | **Discharged in Lean** (`Coverage.lean` `senderStreams_pos_iff`, `Send.lean` `validPools`) |
| **Send A2 (`ExecutePush` starts before external `Finish`)** | `KVCacheManagerWithTransfer::PoolReshardPush` inserts the session into `active_pool_reshard_sends_` and immediately invokes `ExecutePush`, which takes its caller op (`++in_flight_`). | **C++ init discipline** (`KVCacheManagerWithTransfer::PoolReshardPush`) |
| **Send A4 (Per-transfer connection-release window in `EndOp`)** | Under `DataConnectionReuse::kPerTransfer`, the last op (`in_flight_ == 1 && finalizing_`) drops `mu_` in `ReshardSendSession::EndOp` to call `ReleaseDataConnectionsAfterSend` before `--in_flight_` and `SettleLocked()`. Since `finalizing_ == true` and `in_flight_ == 1`, no other op is in flight and `ReshardSendSession::Finish` is a no-op (`if (done_ \|\| finalizing_) return`). | **Simulation soundness argument** (`Send.lean` A4) |

## Observations (`R2a`–`R8`)

| ID | Component & C++ symbol | Summary | Lean witness |
|---|---|---|---|
| **R2a** | `ReshardCoordinator::ExecutePoolReshard` (Stage 1 arm barrier) | **Partial-arm failure orphans already-armed destination receivers.** `ExecutePoolReshard` arms all `dst_units` in parallel threads; if `dst_unit 10` succeeds (creating an active `ReshardReceiveSession` holding a `PoolStagingLease` and active plan) and `dst_unit 11` fails, the coordinator calls `registry_->AbandonClaim` and returns `arm_status` without disarming `dst_unit 10` (and no cancel/unregister control-pipe command exists in `raiden_service.proto` or `KVCacheListener`), leaving its session and staging lease pinned until `timeout_s_`. | Witnessed by `Coordinator.trace_r2a_partial_arm_orphans_armed_receiver`; proved absent under `CleanupPolicy.disarmAndAbandonOnFailure` (`Coordinator.reachable_disarmAndAbandon_no_orphans` in `Coordinator.lean`). |
| **R2b** | `ReshardCoordinator::ExecutePoolReshard` (Stage 2 dispatch barrier) | **sender-dispatch failure leaks the `RequestBlockRegistry` claim and orphans armed receivers.** When any sender RPC fails during Stage 2 (`!sender_status.ok()`), `ExecutePoolReshard` returns `sender_status` without disarming `dst_units` and (unlike the Stage 0/Stage 1 failure returns) without calling `registry_->AbandonClaim(args.req_id, args.uuid, claim_owner)`. Because `RequestBlockRegistry::Complete` is only invoked for sender transfers that succeed, both armed `dst_units` remain orphaned until `timeout_s_` and `claimed_[(req_id, uuid)]` remains pinned in `RequestBlockRegistry` until `ttl_s_` (`PurgeExpiredLifecycleLocked`), blocking `CancelIfUnclaimed` and re-registration (`Register`). | Witnessed by `Coordinator.trace_r2b_dispatch_failure_orphans_receivers_and_claim`; proved absent under `CleanupPolicy.disarmAndAbandonOnFailure` (`Coordinator.reachable_disarmAndAbandon_no_orphans` in `Coordinator.lean`). |
| **R3** | `ReshardReceiveSession::FinishPoolH2d` & `KVCacheManagerWithTransfer::CompleteReadWithDetails` | **`IsReadyToComplete` poll finish on `ReshardReceiveSession` is redundant (non-bug observation).** Unlike `TransferReceiveSession`, `FinishPoolH2d` sets `network_completed_ = true` immediately before calling `Finish` (after latching end-of-transfer metrics), and `ValidateCommonPoolReshardPlan` (called by `ValidatePlan`) forbids zero transferred pools. Thus `IsReadyToComplete() && !IsDraining()` in `CompleteReadWithDetails` cannot fire before the last H2D callback and never skips metrics. | Proved by `Recv.reachable_pollReady_disabled` and `Recv.trace_duration_metric_on_success_and_failure` in `Receive.lean`. |
| **R4** | `ReshardReceiveSession` (`CollectEligiblePoolH2dsLocked`) & `KVCacheManagerBase` | **Rank-ordered H2D waves protect aliased device pages (verified design invariant).** Full-attention pools (`rank = 0`) whose H2D copies span shared hybrid-model device pages always complete before state-class pools (`rank = 1`) launch H2D, so lower-rank padding writes never clobber higher-rank state bytes regardless of network arrival order. | Proved by `Recv.RankWaveOrder` (`rankWaveOrder_iff`) in `Receive.lean` and `Pipeline.AliasedPageCorrect` (`trace_aliased_page_out_of_order_arrival`) in `Pipeline.lean`. |
| **R6** | `ReshardSendSession::RecordPushCompletion`, `ReshardSendSession::Create` & `KVCacheManagerBase::GetBlockChunks` | **early `UnregisterActivePlan` on partial send failure while sibling pools/peers are still in flight.** `RecordPushCompletion` calls `UnregisterActivePlan` as soon as `finalizing_` is latched on the first error even when `in_flight_ > 1`, whereas `EndOp()` already unregisters on settle. A sibling resolving chunks after that (`StartPoolPush` → `AsyncPush` → `BlockTransport::AsyncPushShards` → `BlockTransport::BuildBlockRequests` → `GetBlockChunks`) gets `{}` on bounded staging or silently falls back to full-block un-sliced extents on full-mirror staging. The sharper consequence: with the plan gone, a retry of the same `uuid` passes `Create`'s `RegisterActivePlanDirect` (the `uuid`-uniqueness guard of `RegistrationPolicy.reserveBeforeLease`), shares the draining session's uuid-keyed staging lease, and loses it when that session settles — a third transfer is then leased the same slot. | Witnessed by `Send.trace_early_unregister_on_error_vs_onSettle`; proved safe under `UnregisterPolicy.onSettle` (`Send.reachable_onSettle_plan_iff_done` in `Send.lean`). |
| **R7** | `RequestBlockRegistry::Complete` & `RequestBlockRegistry::AbandonClaim` | **Multi-owner pipelined claims share a single owner-unscoped `completed_units_` set.** `claimed_owners_` supports multiple pipelined destination stages claiming `(req_id, uuid)` under distinct `claim_owner` tokens, but `completed_units_[(req_id, uuid)]` is not scoped by `claim_owner`. Once stage 1's senders vote `Complete` for every unit in `claimed_units_`, `RetireLocked` erases `request_blocks_` and `claimed_owners_` while stage 2's claim is still active, and `AbandonClaim` does not clear `completed_units_`. | Witnessed by `Registry.trace_r7_single_stage_votes_retire_multi_owner_claim` in `Registry.lean`. |
| **R8** | `RequestBlockRegistry` (`PurgeExpiredRequestBlocksLocked`, `PurgeExpiredLifecycleLocked`, `Register`, `CancelIfUnclaimed`, `LookupAndClaim`) | **split TTL expiration between `request_blocks_` and `claimed_` purges registered blocks while a claim is active.** `Register` sets `registration.expires_at = t_0 + ttl_s_`, whereas `LookupAndClaim` at $t_1 > t_0$ sets `claimed_[(req_id, uuid)] = t_1 + ttl_s_` without refreshing `registration.expires_at` on the claimed `request_blocks_` entries (and `CancelIfUnclaimed` purges lifecycle without `request_blocks_`). In $[t_0 + \text{ttl}, t_1 + \text{ttl})$, `PurgeExpiredRequestBlocksLocked` erases `request_blocks_` while `claimed_` is still active, causing a second pipelined `LookupAndClaim` to fail with `"Missing producer block registration"`. | Witnessed by `Registry.trace_r8_split_ttl_purges_request_blocks_while_claim_active` and lockstep expiration proved invariant by `Registry.purgeExpiredAll_inv` in `Registry.lean`. |
